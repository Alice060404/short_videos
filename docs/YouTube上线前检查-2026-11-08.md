## 必须解决的部署阻断项

1. **P1：Nginx 未放行新接口。** `deploy/security/make-nginx.py:69` 的 PHP 入口正则仍只有原 9 个平台，之后的 `/api/` 通用规则返回 404。已通过 SSH 确认 us 的 `/etc/nginx/conf.d/short-videos.conf:104` 和 `:121` 同样如此。只上传前端和 PHP 文件会导致 YouTube 请求返回 404。应将 `youtube/youtube` 纳入原有受限入口，保留限流与 PHP-FPM 设置。
2. **P1：PHP 无法连接内部解析服务。** `api/youtube/youtube.php:9` 使用 `127.0.0.1:8765`；`deploy/security/parser-egress.sh:8` 中的网段列表拒绝整个 `127.0.0.0/8`。已确认服务器实际 iptables 链存在此 REJECT。即使放行 Nginx 并启动服务，PHP 仍会返回服务不可用。应在对应拒绝规则之前仅允许 svparser 连接 `127.0.0.1:8765/TCP`，或改为受控 Unix Socket；不能直接解除全部本机/内网限制。
3. **P1：缺少服务部署与进程托管。** 当前仓库只有本地启动说明，无 YouTube systemd 单元或安装流程；us 没有监听 8765 的进程，服务清单没有 YouTube 单元，当前 release 没有该 PHP 文件。需部署独立虚拟环境、固定版本 yt-dlp/EJS 和解析源码，设置服务用户、重启策略、资源及出站限制，并完成健康检查。us 当前 Python 3.10.12、Node 22.23.4；本地安装的 yt-dlp 要求 Node >=22，已有 Node 版本符合最低版本条件，仍需验证服务 PATH 和 EJS 执行。
