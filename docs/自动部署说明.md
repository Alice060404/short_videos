# GitHub Push 自动部署说明

本项目通过 GitHub Actions（[`.github/workflows/deploy.yml`](../.github/workflows/deploy.yml)）与源站原子发布脚本（[`deploy/ci/server-deploy.py`](../deploy/ci/server-deploy.py)）实现 `push main` 自动测试、构建、部署与失败自动回滚。

## 触发与按变更部署策略

- 推送到 `main` 分支时自动触发（仅修改 `docs/`、`README*.md`、`img/`、`LICENSE` 时跳过）。
- **站点（前端 + PHP API）**：当 `web/`、`api/` 或相关测试变更时，在 CI 中执行 PHP 语法检查、安全/解析单测、Next.js 静态构建与前端测试，通过后流式推送到源站，原子切换 `/var/www/short-videos/current` 并优雅重载 `php8.1-fpm`，完成源站冒烟检查。
- **YouTube 服务**：仅当 `services/youtube/` 或 `tests/youtube_test.py` 变更时，在源站构建新版本独立 venv，切换 `/opt/short-videos-youtube/current` 并重启 `short-videos-youtube.service`、验证 `/health` 与 `/parse`。
- **Cloudflare Worker**：仅当 `cf_sv_proxy/` 变更时运行 `cf_sv_proxy/worker.test.mjs`；若已配置 `CLOUDFLARE_API_TOKEN`，自动执行 `wrangler deploy`（保留已有 Worker Secrets 如 `MEDIA_SIGNING_KEY`）。
- 也可以在 GitHub Actions 页面通过 **Run workflow（workflow_dispatch）** 手动勾选任意组件触发部署。
- Nginx、防火墙（iptables）、PHP-FPM 池及签名密钥**不随普通 push 覆盖**，防止误改影响同机其他服务。

## 必要 GitHub Secrets 配置

在 GitHub 仓库的 **Settings → Secrets and variables → Actions → New repository secret** 中添加：

| Secret 名称 | 是否必填 | 说明 |
|---|---|---|
| `DEPLOY_SSH_HOST` | 必填 | 源站服务器 IP 或域名 |
| `DEPLOY_SSH_PORT` | 必填 | 源站 SSH 端口（留空默认 `22`） |
| `DEPLOY_SSH_USER` | 必填 | 专用低权限部署账号（默认 `svdeploy`） |
| `DEPLOY_SSH_KEY` | 必填 | 专用 `ed25519` 部署私钥完整内容（含 BEGIN/END 行） |
| `DEPLOY_SSH_KNOWN_HOSTS` | 必填 | 源站 SSH 公钥指纹（`ssh-keyscan` 输出，防 MITM） |
| `CLOUDFLARE_API_TOKEN` | 可选 | 需要自动部署 `cf_sv_proxy` Worker 时配置（权限：Workers Scripts Edit） |
| `CLOUDFLARE_ACCOUNT_ID` | 可选 | 配合 `CLOUDFLARE_API_TOKEN` 使用（多账号时必填） |

## 安全设计与回滚

- 源站专用账号 `svdeploy` 的 `authorized_keys` 绑定强制命令 `command="sudo -n /usr/local/sbin/short-videos-deploy",no-port-forwarding,no-X11-forwarding,no-agent-forwarding,no-pty`，无交互式 Shell，仅能通过 stdin 提交受大小与路径校验的 `.tar.gz` 发布包。
- 发布脚本使用文件锁防止并发冲突，校验解压路径与清单、强制生成 `svproxyurl.php` 307 重定向桩、并在源站复跑 PHP 语法与安全测试；激活后任何健康检查失败都会自动回滚到上一版本。
- 发布成功后自动保留最近 5 个站点版本与最近 3 个 YouTube 服务版本，防止磁盘占满。
- 如需在源站手动查看或回滚历史版本：

```sh
sudo /usr/local/sbin/short-videos-deploy --list
sudo /usr/local/sbin/short-videos-deploy --rollback-site <RELEASE_NAME>
sudo /usr/local/sbin/short-videos-deploy --rollback-youtube <RELEASE_NAME>
```
