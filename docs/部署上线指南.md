# 部署上线指南

本文介绍如何把「网页前端（`web/`）+ PHP 解析接口（`api/`）」部署到自己的服务器上并公开上线，以及上线前后需要注意的事项。

> 只想在本地试用，看 [web/README.md](../web/README.md) 的「本地开发」一节就够了。

---

## 一、整体结构

上线后，站点根目录是这样的：

```
站点根目录/
├── index.html      ← 前端页面（来自 web/out/）
├── 404.html
├── _next/          ← 前端静态资源（文件名带哈希，可长期缓存）
├── icon.png
└── api/            ← PHP 解析接口（来自仓库的 api/）
```

请求流程：

```
浏览器 ──粘贴链接──▶ /api/<平台>/xxx.php ──▶ 各平台服务器
   │                     │
   │◀──── JSON（直链）────┘
   │
   ├─ 抖音 / 微博：下载经 /api/svproxyurl.php（或 Cloudflare Worker）中转，补上 Referer
   └─ 其他平台：浏览器直接访问 CDN 直链
```

服务器不保存任何视频或图片。解析历史只存在用户浏览器的 localStorage 里。

## 二、上线前必须处理

### 1. 填写媒体代理的域名白名单

`api/svproxyurl.php` 中的 `$allowedHostSuffixes` 默认为空，表示**可以代理任何公网地址**。公开部署后，别人可以把你的服务器当成免费下载中转站：消耗你的带宽，你的服务器 IP 还会被拿去访问各种网站。

上线前请填写平台的 CDN 域名（按后缀匹配），例如：

```php
$allowedHostSuffixes = [
    // 抖音
    'douyinvod.com', 'douyinpic.com', 'snssdk.com', 'amemv.com', 'zjcdn.com',
    // 微博
    'weibocdn.com', 'sinaimg.cn',
];
```

> 各平台的 CDN 域名会变。填写后，请用抖音、微博的真实链接分别测试视频和图片下载。如果下载时提示“URL 不允许代理”，就把直链里的域名补进白名单。

### 2. 使用生产环境的 php.ini

- 以 `php.ini-production` 为模板，确认 **`display_errors = Off`**。
  部分接口在 PHP 8.4 下会产生 Deprecated 警告（例如 `bilibili.php` 用到的 `CURLOPT_BINARYTRANSFER`）。如果开启了 `display_errors`，警告会混进接口输出，前端就会提示“接口返回的数据格式不正确”。
- 必须启用以下扩展：`curl`、`openssl`、`mbstring`。`json` 在 PHP 8 中默认就有。
- 建议保持 `log_errors = On`，这样错误会写进日志，方便排查。

### 3. 不要用 `php -S` 跑生产环境

`php -S` 是单进程的开发服务器，一个慢请求就会阻塞所有用户。生产环境请使用 **Nginx + PHP-FPM**、Apache，或者宝塔、1Panel 等面板。

### 4. 只上传需要的文件

| 上传 | 不要上传 |
|---|---|
| `web/out/` 下的全部文件 | `.git/`、`.claude/` |
| `api/` 目录 | `web/node_modules/`、`web/.next/`、`web/` 源码 |
| | `docs/`、`README*`、`cf_sv_proxy/` 等仓库文件 |

## 三、构建前端

在**本机**构建，然后上传产物：

```bash
cd web
npm install
npm run build
```

- 构建过程需要访问 Google Fonts 下载字体，国内服务器上通常连不上，所以建议在本机或 CI 中构建。
- 构建产物输出到 `web/out/`。
- 接口地址写在 `web/.env.production` 中，**修改后必须重新构建**才能生效：

| 变量 | 默认值 | 何时修改 |
|---|---|---|
| `NEXT_PUBLIC_API_BASE` | `/api/` | 前端和接口不在同一域名下时，改成完整地址，例如 `https://api.example.com/api/` |
| `NEXT_PUBLIC_PROXY_BASE` | `/api/svproxyurl.php` | 改用 Cloudflare Worker 中转时，填 Worker 地址（见第五节） |

注意：`out/index.html` 会覆盖仓库根目录的轻量版 `index.html`。两个前端只能二选一。

## 四、Nginx 配置示例

以下配置基于 Nginx + PHP-FPM，可以按实际情况调整域名、路径和 PHP-FPM 的 socket。

```nginx
# 限流：按 IP，每分钟 20 次解析请求（写在 http 块中）
limit_req_zone $binary_remote_addr zone=sv_api:10m rate=20r/m;
# 代理下载单独限流：每分钟 30 次
limit_req_zone $binary_remote_addr zone=sv_proxy:10m rate=30r/m;

server {
    listen 443 ssl http2;
    server_name example.com;

    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    root /var/www/unmarked;
    index index.html;

    # 禁止访问隐藏文件（.git、.env 等）
    location ~ /\. { deny all; }

    # 前端静态资源：文件名带哈希，可以长期缓存
    location /_next/static/ {
        add_header Cache-Control "public, max-age=31536000, immutable";
        try_files $uri =404;
    }

    location / {
        try_files $uri $uri.html $uri/ /404.html;
    }

    # 媒体代理：要流式转发大文件，关闭缓冲并放宽超时
    location = /api/svproxyurl.php {
        limit_req zone=sv_proxy burst=10 nodelay;
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_pass unix:/run/php/php8.4-fpm.sock;
        fastcgi_buffering off;
        fastcgi_read_timeout 300s;
    }

    # 解析接口
    location ~ ^/api/.+\.php$ {
        limit_req zone=sv_api burst=10 nodelay;
        limit_req_status 429;
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        fastcgi_pass unix:/run/php/php8.4-fpm.sock;
        fastcgi_read_timeout 60s;
    }

    # api 目录下除 .php 外的文件一律不对外提供（必须写在上面的 .php 正则之后）
    location ~ ^/api/ { deny all; }
}

server {
    listen 80;
    server_name example.com;
    return 301 https://$host$request_uri;
}
```

要点：

- **必须开启 HTTPS**，可以用 Let's Encrypt 的免费证书。否则浏览器的剪贴板读取等功能用不了。
- `/api/svproxyurl.php` 要关闭 `fastcgi_buffering`，否则大视频会先完整缓存到服务器上再发给用户。
- Nginx 先检查 `location =` 精确匹配，然后按书写顺序检查正则，第一个命中的生效。所以 `^/api/.+\.php$` 必须写在 `^/api/` 前面：这样 `.php` 能正常执行，其余文件都会被拒绝访问。不要把后者写成 `location ^~ /api/`，因为 `^~` 前缀一旦命中就会跳过所有正则，`.php` 接口也会被一起拦掉。

## 五、带宽：考虑把代理换成 Cloudflare Worker

抖音和微博的下载会经过 `svproxyurl.php` 中转。**视频有多大，你的服务器就要传输多少流量**。如果服务器带宽小，或者按流量计费，很容易被拖垮。

替代方案：部署仓库中的 [cf_sv_proxy](../cf_sv_proxy/README.md) Worker，把 `NEXT_PUBLIC_PROXY_BASE` 改成 Worker 地址，然后重新构建前端。这样下载流量会走 Cloudflare 的边缘节点，不再占用服务器带宽。

注意：Cloudflare Workers 免费版每天限 10 万次请求。另外，`workers.dev` 域名在国内的访问不稳定，建议绑定自己的域名。

## 六、服务器选址与备案

| | 国内服务器 | 海外服务器 |
|---|---|---|
| 备案 | 域名必须先完成 **ICP 备案**才能访问 | 不需要 |
| 访问速度 | 国内用户访问快 | 取决于线路，香港、日本相对较好 |
| 平台兼容性 | 解析结果最稳定 | 部分平台可能对海外 IP 限流、返回不同数据，甚至直接拒绝请求 |

**购买服务器前，最好先在同一机房的机器上，用各平台的真实链接测试一遍。**

## 七、安全与防滥用

- **限流**：见第四节的 `limit_req`。也可以用 Cloudflare 的 WAF 或速率限制规则。请求太频繁时，平台会先把你的服务器 IP 拉进风控。
- **CORS**：所有接口默认返回 `Access-Control-Allow-Origin: *`，任何网站都能在前端直接调用你的接口。如果不想被别人蹭用，可以把各接口文件里的这行 header 改成只允许你自己的域名。注意这样做只能拦住浏览器里的调用，挡不住服务器直接请求。
- **聚合接口 `api/sv.php`**：新前端不会调用它。如果你也开放这个接口，请在里面的 `$allowedHosts` 中填上你的域名，并保持 `$allowPrivateHosts = false`。
- **SSL 校验**：大部分接口请求上游时都关闭了证书校验（`CURLOPT_SSL_VERIFYPEER => false`）。这是原项目的写法，一般能正常用。如果你的安全要求较高，可以逐个开启校验并配置 CA 证书。
- **日志**：Nginx 的访问日志会记录用户提交的分享链接。请定期清理，或者在隐私说明里告知用户。

## 八、上线后的维护

- **平台改版会让解析失效**。这类接口依赖平台的非公开接口，失效是常态。建议：
  - 关注上游仓库 [jiuhunwl/short_videos](https://github.com/jiuhunwl/short_videos) 的更新，及时合并修复；
  - 为每个平台准备一条测试链接，定时请求检查。例如用 cron 执行下面的命令，判断 `code` 是否为 200，失败时发邮件或推送告警：

    ```bash
    curl -s "https://example.com/api/bilibili/bilibili.php?url=<测试链接>"
    ```
- **新增平台**：要同时修改三个地方：`api/` 中的接口文件、`api/sv.php` 中的 `$platforms`，以及 `web/lib/platforms.ts`。
- **更新前端**：在本机重新构建，然后用新的 `out/` 整体替换线上文件。`_next/static/` 里的旧文件可以删掉。

## 九、合规

- 页面底部和“关于”区块已有版权声明。公开运营时，建议再提供一个**侵权投诉的联系方式**（例如邮箱），收到投诉后及时处理。
- 不要把解析出来的内容用于盈利，比如批量搬运、付费下载。
- 不要提供需要登录或 Cookie 才能访问的内容，比如私密作品、付费内容。
- 国内主体运营时，要遵守网络安全、个人信息保护等相关规定。此类工具也可能被平台投诉，要有心理准备。

## 上线检查清单

- [ ] php.ini 已设置 `display_errors = Off`，并启用了 `curl`、`openssl`、`mbstring`
- [ ] 使用 Nginx/Apache + PHP-FPM，没有使用 `php -S`
- [ ] 只上传了 `web/out/*` 和 `api/`，没有 `.git`、`node_modules`
- [ ] `.env.production` 中的接口地址正确，修改后已重新构建
- [ ] HTTPS 已启用，HTTP 会自动跳转到 HTTPS
- [ ] 已配置限流（Nginx `limit_req` 或 Cloudflare 规则）
- [ ] 已评估代理带宽，必要时改用 Cloudflare Worker
- [ ] 国内服务器已完成 ICP 备案；海外服务器已实测各平台能正常解析
- [ ] 至少用 3 个平台的真实链接，在线上完整走过“解析 → 预览 → 下载”流程
- [ ] 已提供侵权投诉的联系方式
- [ ] 已为各平台设置定时检测
